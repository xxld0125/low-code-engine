# 低代码平台核心架构设计：从原理到工程实践

本文档深度融合了低代码平台的理论设计与一线工程实践。以架构逻辑为主线，补充了具体的 SDK 划分、画布分层实现细节及技术选型建议。

## 1. 核心理念与架构概览 (Core Concepts & Architecture)

### 1.1 低代码的本质

低代码的核心本质在于**解耦**：将 UI 的描述（Description）与 UI 的实现（Implementation）分离开来。

- **UI 描述**：使用标准化的数据结构（Schema/DSL）来表达页面结构。
- **UI 实现**：通过渲染引擎将描述映射为具体的运行时代码或 DOM。

### 1.2 核心能力

- 抽象和建模
- 架构设计

### 1.3 核心功能模块与沉淀产物

平台能力按功能模块划分，通常在 Engineering 中体现为 Monorepo Packages：

**相关概念**：

- 物料编排 -> 组件拖拽
- 物料渲染引擎 -> 组件在页面中的布局渲染
- 数据源管理 -> 数据表
- 流程编辑器(负责配置) + 流程引擎(负责执行 [ 内存型流程引擎、工作流流程引擎 ]) -> 流程编辑
- 资源中心 -> 静态资源管理

| 核心模块       | 功能描述       | 对应 SDK (Package)                    | 技术难点与职责                              |
| :------------- | :------------- | :------------------------------------ | :------------------------------------------ |
| **物料编排**   | 页面搭建与布局 | `layout-engine`                       | 4种布局引擎实现 (Flex/Grid/Canvas/Block)    |
| **物料渲染**   | Schema 转页面  | `material-renderer`                   | 递归渲染、增量更新、主题与多端适配          |
| **数据源管理** | 数据模型与连接 | `online-database`                     | **千万级数据渲染** (Canvas Table)、API 连接 |
| **流程引擎**   | 逻辑编排       | `flow-editor` <br> `flow-interpretor` | 流程编辑器（配置）与流程解释器（运行时）    |
| **资源中心**   | 静态资源管理   | `resource`                            | 大文件断点续传 (`file-uploader`)            |

## 2. 协议与建模 (Protocols & Modeling)

### 2.1 页面描述协议 (Schema)

Schema 是低代码平台的通用语言（DSL），通常采用 JSON 格式。整个平台编排完成之后，存储的数据一定是一个 JSON。

**Schema 关键要素**：

- **组件名称**：指定使用的物料类型。
- **组件属性 (Props)**：配置组件的外观与行为。
- **子节点 (Children)**：嵌套结构，形成组件树。
- **事件绑定 (Events)**：DND 拖拽、Mouse Event 等交互逻辑。
- **数据绑定 (Data Binding)**：连接数据模型与视图。
- ......

### 2.2 数据模型优化

为了性能与维护性，采取**结构与数据分离**策略：

1.  **框架结构 JSON**：描述页面的 DOM 结构与组件关系。
2.  **内容数据 JSON**：存储具体的业务数据。

_渲染顺序：先渲染框架 JSON 生成骨架，再注入数据 JSON 内容。_

## 3. 渲染引擎设计 (Rendering Engine)

### 3.1 核心工作原理

渲染器是 Schema 到 UI 的转换器，用来将 JSON 数据渲染成页面内容的组件。主要运行机制为：

1.  **映射 (Map)**：Schema Type -> 组件物料库代码。
2.  **递归 (Recursion)**：深度优先遍历树结构（Root -> Leaf）。
3.  **策略模式 (Strategy)**：`Renderer` 通过策略模式负责数据加工 -> 数据传递 -> 组件渲染的全流程。

### 3.2 性能优化策略

- **增量更新 (OT)**：引入 Operational Transformation (OT) 算法，对比 JSON Patch，精准识别增、删、改、移。
- **可视区渲染**：针对长列表或复杂画布，仅渲染 Viewport 内容。

### 3.3 渲染器与出码

通常平台会提供 schema 渲染页面的功能，同时也可将所有配置输出 JSON Schema，我们称为**出码功能**。

### 3.4 其他特性

1. 渲染方式
2. 设备兼容
3. 主题定制
   - 样式 token
   - 样式消费

## 4. 编排与布局引擎 (Orchestration & Layout)

低代码平台的物料体系和编排引擎是平台的核心组成部分，其设计目标是支持灵活、高效的页面布局编排，提供良好的开发者体验和用户体验。

### 4.1 布局引擎分类 (Layout Engine)

| 引擎类型        | 描述                           | 应用场景             |
| :-------------- | :----------------------------- | :------------------- |
| **Flex 布局**   | 兼顾灵活与易用，类比 CSS Flex  | 管理后台、CRM、ERP   |
| **Grid 布局**   | 基于网格点坐标 (Grid Points)   | 仪表盘、可视化大屏   |
| **Block 布局**  | 自上而下的流式布局，灵活性较低 | 简单表单、OA、文档流 |
| **Canvas 布局** | 绝对定位，100% 自由灵活性      | 类设计软件、自由绘图 |

### 4.2 编排引擎核心思路

- 基于拖拽的交互模型，实现所见即所得的页面设计
- 引入 flex 布局引擎，支持复杂布局的自动化排列
- 提供布局数据的实时更新与保存能力，便于回显与编辑

### 4.3 画布架构设计 (Canvas Architecture)

编排引擎采用**微内核思想**，核心遵循 `f(state) -> view`，**组合层与渲染层彻底隔离**。

- render runtime(渲染引擎sdk) + dsl(json) = 页面
- 事件：DND拖拽、Mouse Event

#### 4.3.1 画布分层技术 (Layered Canvas)

借鉴浏览器渲染模型，使用冒泡机制穿透，利用 Event Bus 通信：

- **第一层 (渲染层)**：`div` 容器。
  - **职责**：只负责页面渲染。
  - **逻辑**：`render(dsl, document.querySelector("#root"))`。
- **第二层 (交互层)**：覆盖在上面的 `div`。
  - **职责**：处理右键菜单、辅助框选等交互事件。
- **第三层 (事件层)**：最顶层 `div`。
  - **职责**：捕获全局快捷键、全局手势。
- **Event Bus**：所有层可通过 event bus 进行通信。

#### 4.3.2 画布功能及拓展

**简单编排**：

- 物料均为块级，操作简便，不涉及复杂布局问题

**画布灵活编排**：

- 无限画布、引导线(栅格)、吸附对齐、旋转、快捷键、右键、缩放

#### 4.3.3 高级交互实现细节

- **无限画布**：监听滚动事件，每次滚动动态给画布容器增加宽度/高度。
- **辅助引导线**：使用 `div` 绘制（宽/高 1px），绝对定位，可拖动。
- **智能吸附对齐**：
  - **算法**：计算邻近 DOM 节点，每个节点定义 **6个关键点**（四角+中心中点）和 **3条关键线**（横纵中轴）。
  - **逻辑**：当拖拽距离 < 阈值时，自动吸附并将距离设为 0。

### 4.4 配置面板

配置面板就是对物料进行配置，我们需要将数据、视图、操作解耦。

解耦设计：**数据 (Model)**、**视图 (View)**、**操作 (Controller)** 分离。

- **中介者**：权限控制、数据转换 (Transformer)，暴露部分 API。
- **撤销/重做 (Undo/Redo)**：基于快照队列，通过指针移动切换状态。
- **预览**：render(dsl: {type, key, props, animate, actions}, attrs:{}, children)
- **提测、发布**

## 5. 物料体系建设 (Material System)

### 5.1 物料的核心组成

物料最重要的两个东西：

- 数据协议，JSON 数据
- 物料渲染引擎

### 5.2 物料体系设计思路

- 物料以独立、模块化的方式存在，可动态加载与扩展
- 提供灵活的布局能力(如 flex 布局)，支持不同的容器与子组件
- 使用标准化数据协议，支持物料的动态注册、拖拽、渲染及配置

### 5.3 插件化设计

物料管理的核心在于**插件化**，确保新增物料无需修改底座代码。

**前置概念**：

- 插件化基座
- 插件化协议
- 插件生命周期
- 插件开发

**组成**：数据协议 (JSON Schema) + 渲染实现 (Component Code)。

**物料插件化的优点**：

1. **高扩展性**：新增物料无需修改底座代码，只需注册插件
2. **灵活加载**：支持本地与远程物料的无缝加载
3. **解耦性强**：物料与核心逻辑分离，维护成本低
4. **动态化**：支持按需加载，减少初始加载时间

### 5.4 远程物料全生命周期

1.  **构建**：
    - 物料协议
    - 产物模块化规范
2.  **发布**：
    - 上传至资源中心或 NPM。
3.  **加载 (Loading)**：
    - **配置获取**：`fetch/xhr`、`SystemJs`、`modernJs` 获取远程配置。
    - **动态加载**：利用 `SystemJs`、`Module Federation` 或 `modern.js` 的动态 import。
    - **注册物料**
    - **渲染**：异步组件渲染物料。
4.  **优化**：
    - **缓存**：LocalStorage / IndexedDB 避免重复加载。
    - **CDN**：所有产物部署 CDN 加速。
    - **版本管理**：严格的版本控制解决兼容性问题。

### 5.5 实际应用场景

1. **物料市场**：低代码平台的用户可以从市场中挑选需要的物料(组件)并动态加载
2. **动态表单**：表单控件作为物料插件化，通过配置加载不同的控件
3. **动态布局**：根据用户需求，动态加载页面布局物料

## 6. 数据与流程引擎 (Data & Flow Engines)

### 6.1 在线数据源 (Online Database)

数据源、在线多维表

- **高性能表格 (Canvas Table)**：
  - **痛点**：DOM 渲染无法支撑千万级数据。
  - **方案**：直接使用 **Canvas 绘制表格**。
- **字段管理，单元格交互**：
  - 支持 `CellEditor`, `CellRenderer`, `CellValidator` (校验), `CellRules` (权限)。
- **表设计**：
  - Schema(管理字段)
  - 业务表(存储字段数据)
- **外部数据连接**
- **数据消费**：
  - **前端 SQL 编辑器**：低代码化的 Query 模块（在前端实现一个 sql 查询编辑器）。
  - **变量绑定**：简单的变量映射方式。

### 6.2 流程引擎与进阶

- **混合开发**：逻辑编排支持 JSON 配置与 Pro-Code (TS/Flow) 混合使用。
- **逻辑的配置**：使用流程图（flow），最后生成业务逻辑
- **协同编辑**：基于 `CRDT` (Conflict-free Replicated Data Type) 算法，集成 `Yjs` 或 `OT` 方案。

## 9. 技术选型与实战亮点 (Tech Stack & Highlights)

### 9.1 技术选型参考表

| 模块           | 技术方案                                     | 优势                           |
| :------------- | :------------------------------------------- | :----------------------------- |
| **布局引擎**   | Interact.js, CanvasKit, @xflow               | 灵活拖拽与高性能渲染           |
| **数据源管理** | Axios, Apollo Client, PostgreSQL (多 Schema) | 多源接入与动态绑定             |
| **流程引擎**   | XFlow, BPMN 执行引擎                         | 支持复杂流程建模与执行         |
| **多维表格**   | AG Grid, Handsontable, 自研 Canvas Table     | 千万级数据高性能渲染           |
| **工程化**     | Vite, ESLint, PNPM, Docker                   | 快速构建、团队规范、一键化容器 |

### 9.2 实战亮点与难点突破

1.  **Canvas 表格引擎**：突破 DOM 性能瓶颈，支持 1000万行数据流畅渲染与编辑。
2.  **Monaco Editor 集成**：在低代码编辑器中实现了 LSP 服务，提供自动补全与语法提示。
3.  **Copilot 赋能**：集成 `LangChain` + `Node.js`，实现 AI 辅助数据建模与应用创建。
4.  **动态表单**：基于 `Vee-validate` 和 `hook` 钩子，实现了高可维护性的动态表单设计器。
5.  **资源管理**：封装 Webpack Plugin/Loader，实现静态资源自动上传与源码脱敏。
6.  **物料出码功能**：基于 `vue-json-pretty` 封装物料协议数据预览与编辑。
7.  **页面组装模块**：选用通用 `blocksuite` 方案，使页面元素丰富且高度可定制。
8.  **流程引擎及服务编排**：基于鼠标 `move` 事件封装 `vue draggable` 组件实现组件拖拽与页面内容编排。

- 支持任意新增物料组件，并通过统一协议参与布局编排

### 10.4 实时更新与保存

- 支持布局数据的动态更新和持久化保存，适用于低代码平台的页面搭建需求

### 10.5 业务价值

1. 灵活的布局引擎，支持多种场景

1. 模块化设计，支持不同功能解耦
2. 可扩展性强、支持未来新增功能。物料通过插件化体系组织，支持灵活横向扩展
