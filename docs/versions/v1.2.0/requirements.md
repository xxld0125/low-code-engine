# 低代码引擎 v1.2.0 需求文档：平台能力增强与架构完善

## 1. 项目愿景

v1.2.0 旨在补齐低代码平台的**"核心底座能力"**，从"能用的 MVP"向"好用的生产力工具"转型。本版本不追求新增大量组件，而是聚焦于提升**编辑器的交互深度**、**逻辑编排的灵活性**以及**工程化的健壮性**，为后续的智能组件体系打下坚实基础。

---

## 2. 核心功能需求

### 2.1 [P0] 编排与交互引擎 (Layout & Interaction)

提升编辑器的操作效率与专业度，解决"误操作无法挽回"与"布局对齐困难"的痛点。

#### 2.1.1 撤销/重做 (Undo/Redo)

- **历史记录栈**: 维护用户操作的历史记录栈 (History Stack)。
- **操作覆盖**: 支持撤销/重做以下操作：
  - 组件的增删改移。
  - 属性面板的配置变更。
  - 样式的调整。
- **快捷键**: 支持 `Cmd+Z` (Undo) 和 `Cmd+Shift+Z` (Redo)。

#### 2.1.2 高级辅助交互 (Auxiliary Interaction)

- **智能吸附 (Snapping)**: 拖拽组件时，自动吸附到附近组件的边缘或中心轴。
- **辅助引导线 (Ref Lines)**: 拖拽过程中显示动态的对齐辅助线，并标记距离像素值。
- **父级高亮**: 拖拽至嵌套容器时，清晰高亮当前的 Drop Target。

#### 2.1.3 多视图模式 (Multi-Viewport)

- **响应式预览**: 提供切换按钮，在画布中模拟 Desktop (100%), Tablet (768px), Mobile (375px) 等不同视口宽度。
- **画布缩放**: 支持画布内容的缩放 (Zoom In/Out) 以查看全局或细节。

### 2.2 [P1] 动态性与逻辑增强 (Dynamics & Logic)

打破 v1.1.0 "静态页面+简单数据绑定"的限制，引入动态逻辑能力。

#### 2.2.1 组件联动机制 (Component Linkage)

- **表达式显隐**: 在属性面板中，允许通过 JS 表达式控制组件的 `visible` 属性。
  - 示例: `{{ formData.paymentType === 'credit_card' }}`
- **事件通信 (Event Bus)**:
  - 建立全局事件总线。
  - 支持组件触发自定义事件（如 `onChange` 时 `emit('refreshTable')`）。
  - 支持组件监听事件并执行动作（如监听 `refreshTable` 时 `reload()`）。

#### 2.2.2 自定义脚本与沙箱 (Scripting & Sandbox)

- **转换函数**: 在数据绑定中支持简单的转换逻辑。
  - 示例: `{{ row.status === 1 ? 'Active' : 'Inactive' }}`
- **安全执行**: 引入基础的沙箱机制（如 `new Function` + `with` 限制作用域），防止用户脚本污染全局环境或窃取 Token。

### 2.3 [P2] 协议与工程化 (Protocol & Engineering)

增强平台的健壮性与可维护性。

#### 2.3.1 Schema 版本管理

- **发布历史**: 每次保存/发布生成一个新的 Schema Version。
- **版本回滚**: 在 Dashboard 中查看历史版本并支持一键回滚。

#### 2.3.2 基础出码 (Source Code Preview)

- **代码预览**: 在编辑器中提供 "View Code" 按钮。
- **React 代码生成**: 根据当前 Schema，实时生成可读性较高的 React 组件代码（基于 Next.js + shadcn/ui 风格），供开发者复制二次开发。

## 3. 技术挑战

1.  **Undo/Redo 状态管理**:
    - 挑战: 随着 Schema 增大，全量快照 (Snapshot) 会导致内存暴涨。
    - 对策: 采用 Patches (增量补丁) 方案 (如 `immer` 或 `json-patch`) 记录变更。

2.  **沙箱安全性**:
    - 挑战: `new Function` 仍有原型链逃逸风险。
    - 对策: v1.2.0 先做基础隔离（Proxy 拦截全局对象），明确提示安全边界，后续 v1.3 考虑 iframe 强隔离。

3.  **联动性能**:
    - 挑战: 表达式依赖过多可能导致渲染卡顿。
    - 对策: 建立精确的依赖收集机制 (Dependency Collection)，只更新受影响的组件。

---

## 4. 废弃/延期说明 (Deferred)

- **智能表单/表格 (Smart Form/Table)**: 延期至 **v1.3.0**。需等待组件联动与脚本能力完善后再实施。
- **原子组件扩充**: 延期至 **v1.3.0**。优先聚焦已有组件的交互体验优化。
